## 1. 项目总目标与架构边界

目标是开发具有长期连续性的个体 AI：积累真实经历、形成并调整偏好/人格/目标，能够自主思考、等待、拒绝或不行动，并逐步产生兴趣和写作意愿。

关键边界：
- CSD 是长期认知状态的唯一权威所有者。
- DSH / SurfCore 是可替换的平台/运行环境，不拥有 AI 人格与长期记忆。
- QQ、B站等平台只提供外部数据和行动接口。
- ASM 负责外部操作授权、执行、验证和恢复。
- Worker 处理受限外部输入；不能直接访问 CSD 数据库或内部认知状态。
- Worker 的输出是待验证证据/提议；游标与结果元数据必须由 host 验证，不能让 Worker 自行提交 CSD 状态。
- 外部插件和适配器不得直接获得宿主敏感资源权限。
- 用户电脑 GTX 1050 Ti 4GB，项目按云端 API 路线推进，不要转成依赖本地大模型的架构。
- SurfCore 适配 QQ 和 B站的代码已有基础，但没有真实账号连接，也没有完成真实数据接入。

## 4. 最近一轮（2026-11-19）修改

### 4.1 Worker stdio / 终止监督
- adapters/worker_backends/windows_worker_io.py：
  - 不再吞掉 Job terminate、fallback close、process wait、线程清理错误。
  - 检查 TerminateProcess 返回值；只有后续 wait 能确认退出才接受失败返回。
  - 线程启动进入受保护生命周期，只 join 成功启动的线程。
  - Worker 无法确认终止时抛出 WorkerTerminationError，保留主 I/O 错误和 cleanup 错误信息。
- 新增 tests/test_worker_windows_io.py，覆盖 fake Job / process 终止路径。

### 4.2 Native handle ownership / retryable cleanup
- Job Object、WorkerProcess、WorkerPipes：关闭成功后才清空句柄；关闭失败时保留所有权字段供重试。
- Pipe cleanup 尝试关闭所有 endpoint；成功的逐个清空，失败的保留；全部释放后才标记 closed。
- ACL object handle 关闭失败时保留句柄。
- EmptyAppContainerCapabilities 的 SID buffer 在 LocalFree 失败时保留，不标记 closed。
- CreateProcessW 启动失败路径会尝试关闭 thread 和 process 两个句柄；单个失败不阻止另一个的清理，失败句柄仍记录在 PROCESS_INFORMATION。
- 新增/扩展 tests/test_worker_windows_handle_cleanup.py，使用 fake handles 验证失败保留、部分成功与重试；非 Windows 环境通过 create=True 模拟 Windows-only ctypes API。

### 4.3 AppContainer 测试目录布局
- tests/test_worker_windows_process.py 的 per-run runtime 与 writable temp 目录改为创建在 ephemeral AppContainer profile 的 LocalAppData 目录树内。
- runtime 单独授予 read/execute；worker temp 单独授予 read/write 和 Low Integrity。
- 这是测试夹具修正，不是 Windows 原生实测通过的证据。
