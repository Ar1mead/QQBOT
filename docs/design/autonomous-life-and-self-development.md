# 自主生活与持续成长设计提案

> **状态：** 已采纳为后续设计方向；尚未实现。  
> **日期：** 2026-11-19  
> **适用架构：** `docs/architecture/three-layer-cognitive-architecture.md`  
> **实施约束：** 不推翻三层架构，不改变 CSD 的状态权威地位，不绕过 ASM。

## 1. 目的

本提案把近期对开源项目的比较研究转化为本项目可执行的设计方向。目标不是复制某个“数字生命”项目，而是在现有 CSD、认知服务、Life Engine、Diary、Adapters、Runtime 和 ASM 分工上，补充更完整的自主生活与持续成长能力。

本提案描述的是功能目标和设计约束，不代表这些能力已经实现，也不构成对主观意识或真实情绪体验的声明。

## 2. 参考项目与可借鉴机制

| 项目 / 研究 | 借鉴方向 | 本项目中的吸收方式 |
|---|---|---|
| [ai-companion-pi](https://github.com/sonopdx/ai-companion-pi) | 私人 home、周期性醒来、自主选择活动、特殊唤醒请求、主动联系 | 采用私人活动空间、可配置唤醒评估、活动候选和受控联系队列；不照搬固定四小时 cron 或宽泛工具权限 |
| [NeoPsyke](https://github.com/neopsyke/NeoPsyke) | 动机、规划、治理职责分离 | 让“想做什么”“是否值得做”“是否有权限做”分别由认知提案、Life Engine 评估和 ASM/策略门槛处理 |
| [SAKU](https://github.com/omohikane/saku) | 经历回顾、经验总结、自我模型演化 | 建立证据驱动的反思与状态修订流程；日记或模型自述不能自动成为事实 |
| [Orrin](https://github.com/ric-massey/orrin_v3) | 认知状态、注意力、目标和行动选择可检查 | 将状态和决策理由保留为结构化、可审计数据，不把全部控制权交给提示词 |
| [Generative Agents](https://doi.org/10.1145/3586183.3606763) | 记忆流、反思、计划之间的反馈闭环 | 让经历检索与反思真正影响后续计划，并用结果验证计划是否有效 |
| [PSFN](https://github.com/CGIC-AI/psfn-framework) | 持续身份、自我描述与系统推断的区分 | 分开保存观察事实、AI 自述、模型解释和 CSD 接受的状态 |
| [Argus](https://github.com/quarqlabs/argus) | 证据约束、时间推理、定向记忆检索 | 增强来源、发生时间、记录时间、证据引用和按需检索 |
| [Letta](https://github.com/letta-ai/letta) | 核心状态与可检索档案记忆分离 | 只向模型提供与当前任务相关的有限记忆，不把完整历史无差别塞入上下文 |
| [Voyager](https://github.com/MineDojo/Voyager) | 技能积累、失败后改进、可复用能力 | 保存经过验证的技能与策略，并记录适用条件、验证结果和失败边界 |
| [Tamanitomo](https://github.com/tamanitomo/tamanitomo) | 主动消息排队、变更可追踪和可回滚 | 对外联系先进入待发送队列；重要文件和创作修改保留版本与恢复能力 |

这些项目的成熟度、实际运行表现和验证范围并不相同。上述内容是设计参考，不是对其所有能力均已独立复现或验证的结论。

## 3. 对 ai-companion-pi 的具体评估

### 3.1 值得保留的优点

- **AI 有自己的空间：** 日记、创作、研究、对话记录和计划不必全部挤在用户聊天记录里。
- **活动由 AI 选择：** 醒来后可以研究、写作、整理、联系，也可以不做事。
- **允许提出特殊唤醒请求：** 内部候选活动不局限于固定定时任务。
- **私人活动具有连续性：** 旧作品、未完成的想法和长期兴趣可以在后续活动中继续。
- **主动联系被视为一种活动：** AI 不必永远等用户发起对话。

### 3.2 需要改进的地方

1. **固定四小时唤醒不应成为硬规则。** 周期唤醒应可配置，并与事件触发、内部请求结合；定时器只提供评估机会，不强制生成内容。
2. **新模型实例不应只靠 Markdown 文件维持身份。** 文件适合保存可读作品和上下文，但权威状态必须由 CSD 维护，具备来源、版本、置信度、反证和修订历史。
3. **日记不能代替自我模型。** “我对天文学感兴趣”首先是一次自述或候选解释；只有经历、重复选择和反证经过评估后，才能形成可修订的偏好状态。
4. **动机、计划和权限必须分离。** AI 可以请求观察雪景或研究国际空间站，但请求不等于自动获得唤醒资源、网络权限或对外行动权限。
5. **主动联系必须有发送治理。** 先形成待发送内容，再检查用户设置、安静时段、频率上限、重要性和授权；普通内部想法不应自动变成消息。
6. **宽泛工具权限不适合作为默认。** 不照搬跳过权限确认或 unrestricted shell；外部副作用仍须由 ASM 授权、执行和验证。
7. **活动需要结果评价。** 不能把“已启动”当成“已完成”，也不能把持续生成日记当成成长；需要记录目标、实际结果、失败和因果不确定性。
8. **长期项目比随机活动更有价值。** 兴趣可以形成跨多次唤醒的研究或创作项目，支持继续、暂停、恢复、修订和放弃。

## 4. 采纳后的能力设计

### 4.1 私人生活空间（Private Home）

建立独立于聊天记录的私人活动空间，用于保存：
- 日记与反思草稿；
- 已完成和未完成的创作；
- 研究笔记、来源和待验证问题；
- 长期兴趣项目、计划和阶段成果；
- 技能/策略库及其验证记录；
- 写给未来自己的备忘或待续想法。

**权限与数据边界：**
- Private Home 是活动产物与工作资料空间，不是 CSD 的替代品。
- 文件中的自述、引用、模型输出和外部资料都不能自动成为已接受的事实或身份状态。
- 对核心状态的更新必须通过模型提案、证据审查和 CSD 接受。
- 文件修改应有版本记录；支持撤销或恢复。
- 文件系统权限按活动和目录最小化，不给模型默认的全盘访问能力。

### 4.2 时间、唤醒与休息

唤醒分为三种来源：
1. **定时评估：** 按资源预算和用户配置的节律触发状态检查。
2. **事件评估：** 新经历、目标状态变化、已授权观察结果或重要外部事件触发重新评估。
3. **自主请求：** 认知层提出带理由、预期价值、成本和时效的唤醒请求。

唤醒治理至少考虑：
- 最小间隔、冷却时间和每日资源预算；
- 请求的紧迫性、价值、可替代性和过期时间；
- 当前负荷、最近活动和未完成承诺；
- 用户设置的安静时段及允许的主动联系范围。

自主请求只是候选，不得自行更改调度策略、预算或权限。没有值得做的事情时，选择休息或 no-op。不要固定采用 ai-companion-pi 的四小时周期。

### 4.3 兴趣、长期项目与活动生命周期

兴趣来源可以包括：信息缺口、新颖发现、反复关注的问题、未解决矛盾、长期目标和以前主动选择的活动。

活动应经过以下生命周期：
- 候选 → 评估 → 接受/排期 → 执行 → 结果评价；
- 也可以被拒绝、延后、暂停、恢复、停止或放弃。

长期项目应保存：
- 项目来源和最初问题；
- 当前目标、阶段、依赖和未解决事项；
- 已完成工作及证据；
- 资源成本、风险和截止/过期条件；
- 下一步候选与继续/暂停/放弃理由。

Life Engine 负责比较活动和项目优先级；模型只能提交候选，不能把自己的建议直接变成已承诺目标或外部行动。

### 4.4 反思、自我模型与偏好修订

建立周期性或事件触发的反思过程，但不要求每次唤醒都反思或写日记。

反思需要区分：
- 可追溯的观察和经历；
- AI 当时的自述；
- 模型从经历得出的解释；
- CSD 已接受的状态变化；
- 仍然存在的反证和不确定性。

偏好与自我模型必须是可修订假设。重复证据、明确反馈和情境变化可以增强、减弱、限定范围或退役某项判断；一次模糊事件不得永久改写人格。语义审查和 CSD 修订门槛必须先于持久身份变化。

### 4.5 技能与策略积累

将“知道更多”扩展为“能够更好地完成事情”：
- 保存经过验证的操作步骤、研究方法、创作技巧和失败教训；
- 记录技能的来源、适用条件、验证环境、成功率或已知限制；
- 只有在安全、可重复的验证后才提升为可复用技能；
- 技能库不能授予新权限，也不能绕过 ASM；
- 对策略进行版本管理，失败时允许回滚或标记失效。

### 4.6 主动联系与外部交流

主动联系属于对外副作用，不是普通私人写作：
- 模型先提交待发送消息和理由；
- 策略层检查用户许可、渠道、频率、安静时段和重要性；
- 需要的用户确认必须先取得；
- ASM 授权并执行发送，随后记录实际发送结果；
- 发送失败、被取消或过期都应保留状态，不能声称已经联系。

### 4.7 结果学习闭环

每个有明确目的的活动应尽可能比较：
- 原本想达到什么；
- 实际做了什么；
- 得到了什么结果；
- 哪些预测正确或错误；
- 失败原因是否明确，还是仍然不确定；
- 下次是否应调整策略、资源或目标。

结果学习应形成提案，再由相应状态所有者接受；不能因为模型事后写了一段“反思”就自动修改长期状态。

## 5. 与现有三层架构的对应关系

| 现有组件 | 本提案的扩展 |
|---|---|
| CSD（第一层） | 持久化经历、自我模型、偏好、兴趣/项目状态、承诺、活动结果和修订历史；保持唯一权威 |
| 认知服务（第二层） | 记忆检索、反思、动机候选、活动规划、结果评价、技能提案 |
| Life Engine（第二层） | 评估何时醒来、关注什么、选择哪个活动/项目、是否休息或 no-op |
| Diary / Private Home（第三层活动与产物） | 保存私人日记、作品、研究和项目文件；不取代 CSD |
| Runtime / Adapters（第三层） | 提供受限的时间触发、环境观察、研究和创作执行能力 |
| ASM（外部行动边界） | 管理主动联系、外部写入及其他副作用的授权、执行和验证 |

整体循环：

经历/事件 → CSD 检索历史 → 认知服务形成解释和动机候选 → Life Engine 评估活动与时间 → CSD 接受必要的状态提案 → 私人活动或 ASM 授权行动 → 观察结果 → 结果学习与后续修订。

## 6. 明确不照搬的做法

- 不把每四小时唤醒当成硬性义务。
- 不要求每次唤醒必须写日记、创作或联系用户。
- 不让模型通过编辑 Markdown 文件直接修改核心人格或长期记忆。
- 不把模型自述的情绪或兴趣自动视为客观事实。
- 不给模型默认的 unrestricted shell、全盘文件访问或无限网络访问。
- 不允许自主唤醒请求自行提高预算、改变调度策略或扩大权限。
- 不把消息生成等同于消息发送。
- 不以活动数量、日记数量或模型调用次数作为“成长”指标。

## 7. 建议实施顺序

该顺序延续 cognition-first 策略，不得因新增生活机制而跳过最小认知循环。

| 优先级 | 工作 | 验收重点 |
|---|---|---|
| P0 | 完成云端模型驱动的最小认知循环 | 经历可持久化、检索；模型提出受限提案；CSD 明确接受/拒绝；重启后仍可追溯 |
| P1 | 完善经历反思、自我模型和偏好修订 | 区分事实/自述/推断；重复证据和反证可改变偏好；单次模糊事件不能改写身份 |
| P2 | 建立最小私人生活空间 | 日记、作品、研究资料与 CSD 事件分离；文件可版本化和恢复 |
| P3 | 兴趣、长期项目与自主活动选择 | 活动可继续/暂停/恢复/放弃；评估价值、成本、风险和机会成本；允许 no-op |
| P4 | 定时、事件和自主请求唤醒 | 唤醒只触发评估；有预算、冷却、过期和用户边界；不强制产出 |
| P5 | 技能积累与结果评价 | 记录目标/结果/失败；技能有适用范围和验证记录；可失效和回滚 |
| P6 | 主动联系与平台扩展 | 消息队列、频率/时段控制、必要确认和 ASM 授权；平台先只读 |

P2 可以先实现一个简单的本地/运行时 artifact 目录，但不得因此拖延 P0；P4 的具体唤醒频率应由后续资源与运行环境设计决定，不在本提案中预设固定周期。

## 8. 核心验收场景

1. 私人日记或作品可以保存、修订和恢复，但不会自动变成 CSD 事实。
2. 一次自述“我喜欢 X”只形成候选解释；后续重复选择和反证会改变其置信度或适用范围。
3. AI 可以提出研究/创作项目，并在多次活动间保持进度与来源。
4. AI 可以申请一次计划外唤醒，但请求经过预算、冷却、用户策略和时效检查；请求本身不授予权限。
5. 没有值得做的事情时，唤醒评估选择 no-op，不生成无意义内容。
6. 活动失败后，系统保留失败证据和因果不确定性，并可修订策略。
7. 只有经过验证的技能才进入可复用技能库；不适用或失败的技能可被标记、回滚。
8. 主动消息先进入队列；未经许可或不符合发送策略时不能发出。
9. 模型、Runtime 或平台替换后，CSD 状态和私人作品仍可追溯。
10. 所有外部副作用仍经过 ASM；模型和 Worker 无法自行提升权限。

## 9. 目前状态与限制

- 本文是新增设计提案，不代表私人 Home、唤醒调度、长期项目管理、技能库或主动消息队列已经实现。
- 当前 Life Engine 仍是 provider-neutral 的提案/状态脚手架，没有真实云端 deliberator 或生产级调度器。
- 当前云端 grounded-memory provider 已写入仓库，但新增集成测试尚未执行；真实 API smoke test 未进行。
- 当前最小认知循环仍缺少历史记忆上下文、语义审查/偏好修订契约、完整 Life Engine deliberation 和运行时接线。
- 当前 Actions runner allocation 问题仍需单独诊断；不能将未分配 runner 的失败当成测试结果。
- 本提案不改变 PR #1 必须保持 Draft / Open / Unmerged 的规则。
